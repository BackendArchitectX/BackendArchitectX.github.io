# Robot companion artwork and motion

The README character artwork was generated with the built-in image-generation tool from two user-supplied character references. The reference photographs are not included in the public repository.

The interactive page uses a procedural, articulated 3D model with a sculpted face, curved overlapping cap plates, recessed eyes, irises, pupils, eyelids, arms, hands and legs. The head and both eyes aim independently toward the pointer in world space. It includes real-time lighting, textured metal, blinking, waving, a happy hop and a full turn. It uses no character image or billboard. The readable model source is in `assets/robot-companion/robot-model.js`. The MIT-licensed Three.js r160 engine and the material atlas are served from this same repository; no third-party model service or runtime API is required.

The realism revision replaces flat paint with an image-generated material atlas: pitted olive metal, chipped oxblood paint, tarnished brass, and dark composite. Four quadrants are sampled into independent base-color, bump, and roughness textures at runtime. Irises are generated from radial fibers. The software renderer also samples UV textures, shades the geometry, and draws a transparent contact shadow. Reference photographs remain private to the working context and are not published.

The model is an original procedural interpretation of the supplied character, not a scan or an imported film-production mesh. Lighting and appearance differ between the physically based WebGL renderer and the software fallback.

The idle-motion control pauses automatic movement while leaving pointer tracking and requested gestures active. Reduced-motion preferences disable idle movement by default. Pointer events render a new pose immediately, independently of the idle loop. A geometry-projection renderer provides a moving 3D fallback when WebGL is unavailable.

The GitHub profile uses the earlier generated character artwork in a transparent, script-free SVG loop. Its text follows the page theme, and reduced-motion preferences show a still character. The artwork is embedded in the SVG so it renders inside GitHub's image context without external image requests. Pointer tracking runs on the linked interactive page because GitHub sanitizes scripts from READMEs and images do not receive page mouse events.

## Material atlas prompt (built-in image generation)

Use case: product-mockup. Asset type: PBR base-color texture atlas for an actual interactive 3D robot model. The attached robot image is a MATERIAL/COLOR reference only, do not depict the robot. Create one square 2048x2048 texture atlas divided EXACTLY into four equally sized quadrants, no gaps, no borders, no text or labels. Each quadrant is a flat orthographic macro surface sample, entirely fills its quadrant, uniformly lit, with no directional shadows, objects, perspective or specular highlights. TOP LEFT: realistic fine-grained olive-green aged cast metal, mottled bronze patina, dense tiny pitting, subtle pores and micro scratches, warm olive variation with muted worn gold flecks; convincing dense irregular texture like the face of the reference robot, not skin and not grass. TOP RIGHT: deep desaturated oxblood/crimson painted metal, small irregular chipped paint exposing dark brass and brown oxidation beneath, finely scratched, mostly red with edge-like specks, physically weathered not clean plastic. BOTTOM LEFT: aged warm dark brass/copper metal, fine brushed marks and subtle tarnishing, muted brown gold with natural uneven oxidation. BOTTOM RIGHT: nearly black brown worn woven/rubber composite, fine pebbled grain, subtle irregular scratch detail. Every quadrant must have seamless repeatable edges, rich small-scale detail, low-contrast color modulation with no big blobs. No robot silhouette, no icons, no rendering, no background scene. Match the grounded tactile weathering and muted material colors of the reference.

The generated output was 1254 × 1254; the runtime atlas is encoded to 1024 × 1024 WebP for delivery.

## Character prompt

Use case: stylized-concept. Create one transparent full-body character asset, a cuter version of the tiny robot in BOTH attached reference photos. Treat those as identity and material references, not backgrounds. Preserve its recognizable overlapping weathered red/copper tiled pointed cap, mossy olive-green round metal face, very large warm amber glass eyes, tiny red armor body, short legs and small articulated hands. Make it more adorable: an oversized rounded head, softer cheeks, bright affectionate eyes with generous catchlights, a tiny gentle closed smile, a tiny button nose, and short rounded proportions. Retain tactile lightly worn metal and the distinctive cap construction, but soften the grimy/scratched appearance. High quality cinematic 3D character render with soft studio light and clear silhouette; not flat vector art, not pixel art, not a human wearing armor. Front-facing orthographic-ish camera, head straight and level so it can be animated to look around. Entire assembled character visible from pointed cap to toes. Head and cap together about 62% of character height, tiny body below. Show a small clear narrow neck between head and torso. Both arms relaxed down and slightly away from the torso with clear transparent gaps, each hand fully visible and fingers together. Feet slightly separated. Centered character on a genuinely transparent background with generous clear margins; no desert, floor, shadow plane, scenery, other characters, props, text, badges, UI or watermark. Deliver a single fully assembled character, NOT a sprite sheet or a character turnaround.

## Blink prompt

Edit the supplied transparent robot character for one blink frame. Change ONLY the two eyes inside their existing amber metal rims: close both eyelids into a gentle happy blink, with softly curved olive-green metal eyelids matching the face texture. Preserve the amber eye rims. Everything else must stay exactly the same: same character identity, cap shape and copper tiles, smile, face, body, limbs, pose, proportions, lighting, full-body framing, canvas size, margins and transparent alpha background. Do not move or resize any feature. This is an aligned alternate expression for animation, not a redesign. No text, scenery or other objects.
